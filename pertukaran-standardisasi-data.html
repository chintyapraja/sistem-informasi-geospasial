Pertukaran dan standardisasi data

Data dapat dibuka oleh perangkat lunak lain tetapi tetap gagal digunakan bersama. Pertukaran yang baik memerlukan kesesuaian format, struktur, makna, referensi spasial, kualitas, dan metadata.

1. Tujuan pembelajaran

PertukaranMemilih format dan layanan

Membedakan file, basis data, dan layanan web.

StandarMenyamakan aturan

Memahami sintaks, skema, semantik, CRS, dan metadata.

InteroperabilitasMenggunakan data bersama

Menilai apakah sistem dapat bertukar dan menafsirkan data dengan benar.

2. Format bukan standar

FORMATCara data dikodekan

Contoh: GeoPackage, GeoJSON, GeoTIFF, CSV, atau basis data spasial.

STANDARAturan bersama

Mengatur struktur, istilah, metadata, layanan, kualitas, atau cara akses.

Interoperabilitas adalah kemampuan sistem yang berbeda untuk bertukar data dan menggunakan maknanya secara benar. Berhasil mengimpor file belum cukup apabila kode, satuan, CRS, atau definisinya berbeda.

4. Peta, fitur, dan API

WMS

Mengirim representasi peta sebagai gambar bereferensi geografis. Cocok untuk melihat tampilan, bukan menyunting fitur.

WFS

Memberi akses pada fitur beserta geometrinya. Mendukung permintaan fitur secara lebih rinci.

OGC API — Features

Memberi akses tingkat fitur melalui pola API web modern dan kueri koleksi.

Unduhan berkas

Mengirim salinan dataset. Pengguna perlu memahami versi, lisensi, dan tanggal pemutakhiran.

5. Apa yang perlu distandardisasi?

  • CRS, datum, satuan, ketelitian, dan tipe geometri.
  • Nama, tipe, panjang field, domain nilai, kode, dan relasi tabel.
  • Definisi setiap objek dan atribut agar maknanya tidak ambigu.
  • Waktu berlaku, frekuensi pemutakhiran, penanggung jawab, dan versi.
  • Metadata, lisensi, kualitas, lineage, serta aturan akses.

6. Katalog Unsur Geografi Indonesia (KUGI)

KUGI dari Badan Informasi Geospasial memberikan acuan pengkodean, tipe unsur, atribut, asosiasi, dan aturan dokumentasi unsur geografi. Tujuannya adalah membantu produsen dan pengguna memakai struktur serta istilah yang konsisten. KUGI disusun berdasarkan kerangka SNI ISO 19110 tentang katalogisasi fitur.

7. Metadata: data tentang data

Identitas
Judul, abstrak, tema, kata kunci, dan penanggung jawab.
Cakupan
Wilayah, waktu, skala, resolusi, dan extent.
Referensi
CRS, datum, satuan, serta sistem koordinat.
Kualitas
Sumber, proses, ketelitian, kelengkapan, dan keterbatasan.
Distribusi
Format, layanan, lisensi, biaya, dan cara memperoleh data.
Pemutakhiran
Tanggal, versi, frekuensi, serta kontak pengelola.

8. Prosedur pertukaran dan standardisasi

  1. Inventarisasi sumber, pemilik, versi, tujuan, format, CRS, skema, dan metadata.
  2. Tetapkan spesifikasi target: model data, sistem referensi, aturan kode, satuan, dan kualitas minimum.
  3. Buat pemetaan field dan domain nilai; dokumentasikan perubahan makna.
  4. Konversi format, transformasi CRS, harmonisasi geometri, atribut, dan kode.
  5. Validasi jumlah objek, nilai, topologi, extent, dan sampel hasil.
  6. Lengkapi metadata, lisensi, catatan transformasi, serta versi keluaran.

9. Studi kasus: data fasilitas lintas instansi

Kasus: tiga instansi mempunyai data fasilitas kesehatan dengan nama field, kode jenis, satuan kapasitas, tahun, dan CRS yang berbeda.

10. Lembar analisis standardisasi

Pilih dua dataset sejenis. Susun tabel perbandingan format, CRS, geometri, skema, kode, satuan, waktu, kualitas, metadata, dan lisensi. Tentukan spesifikasi target serta lima pemeriksaan setelah konversi.

11. Ringkasan

  • Formatmengatur cara data dikodekan dan dipindahkan.
  • Standarmenyamakan aturan teknis dan makna.
  • Metadatamenjelaskan identitas, cakupan, kualitas, dan distribusi.
  • Interoperabilitasmemerlukan kesesuaian sintaks, skema, semantik, dan referensi.
